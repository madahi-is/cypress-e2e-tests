# ID: CS15

Título: El cliente de prueba omite la versión Inertia al consultar el rechazo de eliminación

Estado: Actual; error de protocolo en automatización

Prioridad: Media

Severidad: Media

Encargado: Sin asignar

Clasificación: Error de automatización

## Descripción

Después de DELETE, el test consulta GET /grupos con X-Inertia:true sin X-Inertia-Version. El servidor devuelve el 409 de actualización Inertia con X-Inertia-Location. Esto no evidencia que el grupo o sus relaciones hayan sido eliminados.

Casos relacionados: HU09-29 B y C.

## Precondiciones

Instancia aislada income-e2e; base app_e2e; URL local http://localhost:8082/ (http://web dentro del runner). Fixtures independientes HU-9. Administrador admin.e2e@example.test, contraseña E2ePassword!2026. Cypress 16.1.1; Node v22.0.0; la salida identifica Electron 41.7.0 / Chrome 146 en Linux. No se usó el entorno Windows/Brave del ejemplo. Fecha exacta de inicio no suministrada; el fragmento HTTP contiene 15/10/2026 04:46 UTC.

## Pasos y datos de entrada

| Paso | Acción | Datos de entrada |
|---:|---|---|
| 1 | Autenticarse como administrador | Grupo B o C del fixture con relaciones |
| 2 | Solicitar eliminación directa con CSRF | DELETE /grupos/{id}; el test alcanza el siguiente paso tras 302 |
| 3 | Consultar el flash usando el helper actual | GET /grupos; X-Inertia:true sin versión |

Resultado actual: HTTP 409, X-Inertia-Location:http://web/grupos y versión 5682df0eb334903d98e9eda3b6c28cdc. cy.request se detiene antes de comprobar flash y BD.

Resultado esperado: El cliente debe respetar la versión/protocolo Inertia real y comprobar después el mensaje exacto y la conservación de relaciones. No cambiar la expectativa funcional.
